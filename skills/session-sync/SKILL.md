# 会话同步

主会话和它 fork 或派生出来的子会话常常共用同一个工作目录，文件本来就是同步的；它们缺的是**对方不知道的事**：做了哪些决定、完成了什么、改了哪些机器上的东西、还有什么等用户定。这个 skill 把这些整理成一条消息发给对方，让对方接着干活时不会基于过时的认识。

## 1. 先把要用的工具加载上

这些工具多半是延迟加载的，先一次性加载：

```
ToolSearch select:mcp__ccd_session_mgmt__get_session,mcp__ccd_session_mgmt__list_sessions,SendMessage
```

会话管理工具（`mcp__ccd_session_mgmt__*`）由 Claude 桌面版提供。加载不到时，告诉用户这个 skill 需要在 Claude 桌面版的会话里使用，然后结束。

## 2. 判断自己是主会话还是子会话

调用 `get_session`，参数 `"self"`：

- 结果里**有 `parentSessionId`**：自己是子会话，接收方是：
  - 这个父会话（`detached: true` 只表示被挪到了顶层，仍然发给它），收完整汇总；
  - 兄弟会话：调用 `list_sessions {"linked": true}`，`startedBy` 等于父会话 sessionId 的（结果本身不含自己），收精简版，见第 4 步。没有兄弟会话就只发父会话。
- **没有 `parentSessionId`**：自己是主会话。调用 `list_sessions {"linked": true}`，`startedBy` 等于自己 sessionId 的就是直接的子会话，全部作为接收方。一个都没有时告诉用户"没有找到子会话"，结束。

同时记下每个接收方的 `createdAt`（子会话的创建时刻就是 fork 的时刻），下一步要用。

## 3. 确定从哪里开始算

对每个接收方，起点取下面两者中较晚的：

- **fork 时刻**：主→子用该子会话的 `createdAt`；子→主、子→兄弟都用自己的 `createdAt`。
- **上次同步**：在本会话里往回找，最近一次发给这个接收方的同步消息（`SendMessage` 的 `to` 是它）。找到就从那之后算，避免重复。

对方之前发来的汇报（`<cross-session-message from="...">`）说明它已经知道哪些事，这些不要再发回给它。

## 4. 收集对方不知道的事

从本会话起点之后的内容里挑，按对对方接着干活的用处排序：

1. **用户的决定和要求**：定下的方案、否掉的方案、新的约定或偏好（包括新存的记忆）。这是最容易漏、也最重要的。
2. **完成的工作**：做了什么、结果如何、数字和结论（只写结论，不贴过程）。
3. **改动**：
   - 在 git 仓库里工作时，跑 `git log --since=<起点的 ISO 时间> --oneline`（必要时加 `--all`），列出提交号和一句话说明；再给出当前 HEAD 和工作区是否干净。共用同一目录时注明"代码已是最新"，对方不用再拉。
   - 仓库之外的改动：其他机器上的文件、服务、部署、删除了什么。
4. **待办与待定**：还没做完的、等用户决定的、约好以后再提的（带上日期）。
5. **主→子时**：其他子会话做的事，与该子会话的工作相关时简要带一句；该子会话自己做的事不要发回给它。

**子→兄弟的精简版**只挑会影响对方接着干活的事，其余留给主会话：

- 共用代码的改动：改了的接口、公共头文件、消息结构、目录与命名，以及对应的提交号；
- 用户新定的、适用于整个项目的约定和偏好（包括新存的记忆）；
- 仓库之外、对方也会用到的改动：机器上的文件、服务、部署。

只属于本会话任务内部的进展、讨论过程、待定事项不发给兄弟。挑完一条都没有时，这个兄弟就不发，向用户汇报时说一句"与某某无关，未发"。宁可少发，也不要让兄弟会话被无关消息打断。

不要写进去的：
- 密码、认证码、密钥、令牌等凭据，以及账号、用户 ID 这类身份信息；
- 大段代码、diff、日志原文；
- 对方本来就知道的事、与对方工作无关的闲聊。

## 5. 写消息

- **第一行**单独成句、说明这是什么，因为对方的用户在预览里只看到第一行。例如：`主会话同步：你 fork 之后的改动与决定（HEAD 1a2b3c4）` 或 `子会话「数据导入」同步：历史数据导入已完成`。
- 发给兄弟会话的第一行写明来源与要点，例如：`兄弟会话「会话接口」同步：Hooks::onRequest 改为只传原文（提交 1a2b3c4）`。
- 正文用编号分组（决定 / 完成 / 改动 / 待定），每条一两句，整条消息尽量控制在 25 行以内；精简版通常几行就够。
- 语言跟用户平时用的一致。
- 结尾写"不需要回复"。只有确实需要对方确认或接手某件事时，才写清楚要它做什么，而且只请它转告它的用户、由用户决定，不要让对方替本会话去做本会话没被允许做的事。

## 6. 发送

- 每个接收方单独一条，用 `SendMessage`，`to` 填对方的 sessionId，`summary` 写一句简短标签。几个接收方的消息可以在同一轮里并行发出。
- 发送成功只表示送达对方的收件箱，不代表对方已读。如果返回了 `[Cross-session delivery notice]`（对方扣住或拒收），如实告诉用户。

## 7. 向用户汇报

简短说明发给了谁（用 `[会话标题](#sessionId)` 链接），各自同步了哪几类内容，哪些兄弟会话因为无关没发；说明对方是否已读这边看不到。如果有不确定、没写进去的内容，也说一句。
