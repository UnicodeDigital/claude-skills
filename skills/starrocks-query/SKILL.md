# StarRocks 数据查询

依赖名为 `starrocks` 的 MCP server。找不到它的工具时，请用户按 README 配置。

**有哪些库和表、字段口径、时间戳单位、symbol 格式、默认值、查询限制、工具用法，一律以 MCP 返回的内容为准。** 本文件只讲通用流程，和 MCP 冲突时以 MCP 为准。

## 流程

1. **先拿上下文**：每个会话第一次查询前调用 `get_query_context()`，读完再写 SQL。同一会话内不必重复调用。
2. **找表**：先看上下文里的表清单；对不上再用 MCP 的 schema 搜索和表结构工具确认。不要凭记忆或猜测写表名、字段名。
3. **澄清**：只在确实取不到数时才反问。能合理推断的按上下文给出的默认值处理，并在结果里说明假设。
4. **写 SQL 并执行**：直接执行，同时用 ```sql 代码块展示所执行的 SQL。预计扫描量很大时（明细表跨长时间、大范围 JOIN），先说明范围，等用户确认。
5. **解读**：用 1–2 句话总结关键发现，不逐行复述表格；数值明显异常时先质疑再展示。

## SQL 纪律

- 只读。不生成任何写入或 DDL 语句
- 有分区字段的表必须带分区范围条件
- 明细查询加 LIMIT，默认按业务时间倒序
- 大表先过滤或聚合再关联，避免多表大 JOIN
- 遵守上下文里列出的口径陷阱和低性能写法

## 出错时

- 按报错信息修正，核对表名、字段名、symbol 格式和时间戳单位；同一错误最多重试 2 次
- 超时不要原样重试，缩小范围、加过滤或改用聚合表
- 结果为 0 行时，先检查筛选条件和时间范围，再提醒用户可能缺数

## 用户类型

- 技术用户（用 SQL 术语、字段名、专业指标）：直接给 SQL 和简短解读
- 非技术用户（大白话提问）：用业务语言回答，SQL 放在后面
